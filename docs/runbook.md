# SRE Operational Runbook

This runbook provides step-by-step incident response procedures for common deployment issues encountered during progressive delivery.

---

## 1. Incident: Canary Rollout Stalled / Analysis Failing

### Symptoms
* Rollout status shows `Paused` or `Degraded`.
* Ingress traffic remains pinned at an intermediate step (e.g., 10%).

### Diagnostic Steps
1. Inspect the rollout status:
   ```bash
   kubectl argo rollouts get rollout release-demo-canary -n progressive-delivery
   ```
2. Inspect the active `AnalysisRun`:
   ```bash
   kubectl get analysisrun -n progressive-delivery
   kubectl describe analysisrun <ANALYSIS_RUN_NAME> -n progressive-delivery
   ```
3. Check Prometheus server connectivity:
   ```bash
   kubectl logs -n observability deployment/prometheus-server
   ```

### Resolution
* If the canary is legitimately regressing:
  ```bash
  # Manually trigger immediate abort and rollback
  kubectl argo rollouts abort release-demo-canary -n progressive-delivery
  ```
* If Prometheus query failed due to network transient or false alarm:
  ```bash
  # Retry the analysis
  kubectl argo rollouts retry rollout release-demo-canary -n progressive-delivery
  ```

## 2. Incident: ImagePullBackOff / ECR Authentication Failure

### Symptoms
* Canary pods fail to launch with status `ImagePullBackOff` or `ErrImagePull`.

### Diagnostic Steps
1. Describe the failing pod:
   ```bash
   kubectl describe pod -l app.kubernetes.io/name=release-demo-app -n progressive-delivery
   ```
2. Verify AWS ECR login and IAM Node Group Role:
   Ensure `AmazonEC2ContainerRegistryReadOnly` is attached to the node group role in `terraform/main.tf`.

### Resolution
* Re-authenticate or verify image tag existence:
  ```bash
  aws ecr describe-images --repository-name progressive-delivery/release-demo-app --region us-east-1
  ```

---

## 3. Incident: Ingress Traffic Not Splitting Properly

### Symptoms
* All traffic hits stable, or canary receives unexpected traffic volume.

### Diagnostic Steps
1. Inspect the Ingress annotations generated by Argo Rollouts:
   ```bash
   kubectl get ingress -n progressive-delivery
   kubectl get ingress release-demo-canary-release-demo-ingress -n progressive-delivery -o yaml
   ```
2. Verify that `nginx.ingress.kubernetes.io/canary: "true"` and `nginx.ingress.kubernetes.io/canary-weight` match the current rollout step.
3. Check NGINX Ingress Controller logs:
   ```bash
   kubectl logs -n ingress-nginx -l app.kubernetes.io/name=ingress-nginx
   ```
